1. Datalogiskt tänkande
   Vi bröt ner uppgiften genom att först identifiera systemets tre huvudkomponenter och dela ut dem som ansvarsområden (Robin: Medlem, Vasyl: Register, Angelica: Main).
   Och vi kommunicerade via discord i en privat grupp. Varje person ansvarade att baskraven skulle uppfyllas för varje klass.

2. Klass vs Objekt
   Medlems är egen klass för att den samlar information om en medlem som namn och medlemsnummer och skyddar med privata fält. Det privata fältet håller medlemsdatan åtskild från Main, som ansvarar för menyn och inmatning.

3. Samarbete i Git
   Vi valde feature-branches där vi delade upp kodningen. För att undvika att skriva över varandras arbete var vi noga med att kommunicera i chatt gruppen och köra git pull origin main för att synka vår lokala branch innan vi integrerade ny kod. I framtiden kan det vara gynsamt att ha en checklista i main som varje gruppmedlem kan bocka av för att underlätta för varandra.

4. Ett problem ni löste
   Ett stavfel upptäcktes och åter gärdades med hjälp av AI.

5. Reflektion kring AI och externa hjälpmedel
   Vi har använt AI som bollplank, när man behövde ha hjälp med att komma på något mer att göra eller fixa något man sitter fast med.
   Ett exempel är när Robin var klar med Medlem så visste han ej vad mer han skulle göra så han frågade AI om tips på vad han kunde lägga till för klass.
   Eller när Angelica bad AI om koden är rätt, och AI upptäckte ett stavfel som korrigerades.
